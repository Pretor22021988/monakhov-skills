# Подбор практики высших судов под правовые тезисы

Назначение: на входе — набор правовых тезисов (или документ, из которого их надо
извлечь). На выходе — по каждому тезису две раздельные подборки актов высших судов
РФ: **подтверждающая** (pro) и **опровергающая / ограничивающая** (contra). Скилл —
не генератор позиции и не советчик: он находит и классифицирует акты, оставляя
правовую оценку юристу.

Практику берём ИСКЛЮЧИТЕЛЬНО из коннекторов CasusLegal. Базовый — «Высшие суды».
Каждый коннектор сам несёт методику иерархии судов (КС → Пленум и обзоры ВС →
коллегии ВС → ВАС) и правила честности — им доверяем и не переизобретаем. Задача
скилла — задать коннектору правильные запросы (и за, и против) и аккуратно
разложить результат. Корпус под тезис выбирается по его ПРЕДМЕТУ:
- **СИП** (`sip_search_practice`, `sip_find_term`, `sip_get_case_details`,
  `sip_browse_practice`) — интеллектуальная собственность: товарные знаки, патенты,
  авторские и смежные права, средства индивидуализации, домены, недобросовестная
  конкуренция.
- **КАС** (`kas_search_practice`, `kas_find_term`, `kas_get_case_details`,
  `kas_browse_practice`) — практика Судебной коллегии по административным делам ВС РФ
  (СКАД): административное судопроизводство (КАС РФ) и нормоконтроль (оспаривание
  нормативных и иных актов, кадастровая стоимость, избирательные споры, госнадзор
  и т. п.).
- всё остальное — «Высшие суды» (`casuslegal_*`).
В одном наборе разные тезисы могут опираться на разные коннекторы; и pro-, и
contra-заход по тезису идут по одному и тому же выбранному корпусу.

## Когда НЕ применять

- Нужно одно конкретное дело по номеру/реквизитам — достаточно обычного поиска.
- Вопрос «какова позиция по X» без задачи проверить тезис на прочность — это
  обычный режим коннектора, скилл избыточен.

## Жёсткие правила (нарушение обесценивает работу)

1. **Никаких выдуманных актов.** Реквизиты, даты, номера дел, номера пунктов
   постановлений Пленума и обзоров — только из выдачи коннектора в этой сессии.
   Нет акта в базе — так и пиши: «в базе коннектора не найдено», предложи проверить
   по официальному источнику. Не подменяй отсутствие натянутым делом.
2. **Цитаты — дословно.** Любой фрагмент в кавычках «...» — посимвольная копия из
   `sections` (get_case_details), `matched_quotes` (find_term) или инлайн-поля
   `position` (акты КС). НЕ цитируй по полю `snippet` (оно обрезано) и НЕ по памяти.
   Не дописывай в цитату слова тезиса, которых в тексте акта нет.
3. **Не квалифицируй значимость акта за юриста.** Без эпитетов «ключевой»,
   «важнейший», «основополагающий». Подавай реквизиты и суть; вес определит юрист.
4. **Contra ищется отдельно и намеренно.** Если по тезису не запущен контр-поиск с
   переформулированием — работа не сделана. Пустой раздел contra допустим только
   после реального контр-поиска, и тогда он так и помечается.

## Процесс

### Шаг 1. Получить тезисы

Если пользователь дал готовый список — работай с ним.

Если дан документ — извлеки из него атомарные правовые тезисы:
- один тезис = одно правило со следствием (правило → последствие/санкция);
- очисти от фактуры конкретного дела (имена, суммы, номера договоров, даты), оставь
  переносимую юридическую конструкцию;
- сохрани нормативную привязку, если она в тексте есть (статьи кодексов, пункты
  постановлений Пленума);
- разнеси сцепленные доводы на отдельные тезисы (процессуальное и материальное — врозь).

Для документа на 5+ тезисов покажи извлечённый список пользователю и дождись
подтверждения/правок, прежде чем уходить в поиск. Для готового короткого списка —
сразу к шагу 2.

### Шаг 2. Разметить каждый тезис перед поиском

Для каждого тезиса зафиксируй (для себя, кратко):
- **нормы** — статьи и кодекс (важно: фильтр `article` коннектора учитывает кодекс,
  «ст. 65 ГК» ≠ «ст. 65 АПК»);
- **ключевые юридические обороты** — термины, которыми позиция формулируется в актах
  (для дословного поиска и для bm25);
- **формулу contra** — во что превращается тезис, если его опровергнуть или ограничить
  (см. references/reformulation.md — это основной инструмент скилла).

### Шаг 3. Два встречных поиска по каждому тезису

Сначала выбери корпус по предмету тезиса (см. раздел про источник практики):
«Высшие суды» по умолчанию, СИП для интеллектуальной собственности, КАС для
административных дел и нормоконтроля. Инструменты ниже названы для «Высших судов»;
для СИП и КАС используй их одноимённые аналоги (`sip_*`, `kas_*`) — параметры те же.

**PRO-заход.** Запрос — тезис в его собственной формулировке.
- Доктринальная/абстрактная формулировка → `casuslegal_search_practice`,
  `mode='hybrid'` (по умолчанию) или `'semantic'`.
- Привязка к конкретной статье → добавь `article` (напр. `article='ст. 333 ГК'`),
  при необходимости `mode='bm25'`.
- Дословный устойчивый оборот, по которому надо собрать все упоминания
  (напр. «сальдирование встречных предоставлений») → `casuslegal_find_term`.
- `limit` 15–20, чтобы увидеть линию практики, а не один акт.

**CONTRA-заход.** Запрос — тезис, переформулированный в исключение/противоположность
по шаблонам из references/reformulation.md. Это отдельный вызов (или несколько):
семантический по контр-формулировке + точечный bm25/find_term по характерным оборотам
исключения («само по себе не является», «не влечёт», «при условии», «за исключением»,
«не лишает права»).

Коннектор сам упорядочит выдачу по иерархии судов и пометит расхождения и устаревание
(`reform_risk`, `superseded_by`). Не переопределяй эту иерархию — используй её.

**Всегда просматривай отдельные блоки выдачи `constitutional_context` и
`latest_practice`, а не только основной список `results`.** В `results` позиция КС и
свежие определения коллегий тонут из-за тематической близости старых актов. Именно в
`constitutional_context` чаще всего обнаруживается прямая контр-позиция (постановление
КС, опровергающее тезис), а в `latest_practice` — свежая действующая линия коллегий ВС.
Контр-материал по тезису может лежать целиком в этих блоках и не попасть в `results` —
проверяй их по каждому заходу, и по PRO, и по CONTRA. У коннектора КАС этих обзорных
блоков нет (корпус правоприменения) — там полнота контр-поиска обеспечивается
формулировкой запроса, постраничной навигацией и `kas_find_term` по оборотам
исключения.

### Шаг 4. Классифицировать найденное относительно тезиса

По каждому акту реши, что он делает с тезисом:
- **PRO** — поддерживает правило тезиса.
- **CONTRA** — устанавливает обратное правило, либо исключение/условие, при котором
  правило тезиса не работает, либо сужает его сферу.

Помни: **один акт может быть и тем, и другим.** Акт, подтверждающий тезис в общем
виде, но вводящий исключение, — это одновременно pro по правилу и contra по границе.
Указывай обе роли с пояснением, что именно акт подтверждает и что ограничивает.

Прежде чем исключить акт КС как «не по теме» — открой его через get_case_details:
у актов КС сниппет и теги привязаны к фабуле дела, а конституционно-правовой смысл
нормы применим шире (правило самого коннектора).

### Шаг 5. Достать дословные цитаты у опорных актов

Для нескольких опорных по каждой стороне актов (до 3–5 на сторону) вызови
`get_case_details(case_id)` того коннектора, из которого акт найден, и возьми точную
цитату из `sections`.
У актов КС полный текст позиции уже в инлайн-поле `position` — отдельный вызов не нужен.
Остальные акты подавай реквизитами + сутью без обязательной цитаты.

### Шаг 6. Сформировать вывод

Формат и пример — в references/output-format.md. Кратко: по каждому тезису блок с
двумя разделами (подтверждающая / опровергающая), внутри — перечень актов сверху вниз
по иерархии и свежести, у опорных — дословная цитата. Если контр-поиск ничего не дал —
явная строка «Опровергающей практики в базе коннектора не найдено».

  типовых процессуальных и материально-правовых конструкций. Читать на шаге 2.
- `references/output-format.md` — структура итогового вывода и проработанный пример.
