# Проверка судебного акта на соответствие практике высших судов

Назначение: на входе — судебный акт нижестоящего суда. На выходе — по каждому
правовому тезису из мотивировочной части акта: статус соответствия практике высших
судов РФ (подтверждён / расхождение / не охвачен), конкретные акты с указанием
иерархического веса и, при расхождении, — точная суть противоречия.

Практику берём ИСКЛЮЧИТЕЛЬНО из коннекторов CasusLegal. Базовый — «Высшие суды»
(`casuslegal_search_practice`, `casuslegal_find_term`, `casuslegal_get_case_details`).
Для отдельных предметных областей те же приёмы применяются к специализированным
коннекторам, корпус выбирается по предмету тезиса:
- **СИП** (`sip_search_practice`, `sip_find_term`, `sip_get_case_details`,
  `sip_browse_practice`) — интеллектуальная собственность: товарные знаки, патенты,
  авторские и смежные права, средства индивидуализации, домены, недобросовестная
  конкуренция.
- **КАС** (`kas_search_practice`, `kas_find_term`, `kas_get_case_details`,
  `kas_browse_practice`) — практика Судебной коллегии по административным делам ВС РФ
  (СКАД): административное судопроизводство (КАС РФ) и нормоконтроль (оспаривание
  нормативных и иных актов, кадастровая стоимость, избирательные споры, госнадзор
  и т. п.). Особенно уместен при проверке акта по административному делу или
  нормоконтролю.
Имена инструментов в шагах ниже даны для «Высших судов»; для тезисов по
интеллектуальной собственности или административным делам бери одноимённые аналоги
(`sip_*`, `kas_*`) — логика и параметры те же. В одном акте разные тезисы могут
сверяться по разным коннекторам.

## Иерархия источников

Вес найденного акта определяет серьёзность расхождения. Иерархия (от высшего к
низшему):

1. **Постановление КС РФ** — наивысший авторитет; расхождение с ним = грубое
   нарушение конституционно-правового смысла нормы.
2. **Постановление Пленума ВС РФ / Пленума ВАС РФ** — обязательное толкование для
   всех судов; расхождение = системная ошибка суда.
3. **Информационное письмо Президиума ВАС РФ / Обзор судебной практики Президиума
   ВС РФ** — официальная рекомендательная позиция; расхождение = существенное
   отклонение от устойчивой линии.
4. **Постановление Президиума ВАС РФ** — прецедентная позиция по конкретному делу;
   расхождение = отход от сложившейся практики.
5. **Определение СКЭС / СКГД / СКАД и других коллегий ВС РФ** — текущая практика
   коллегий (для административных дел и нормоконтроля — Судебная коллегия по
   административным делам, корпус КАС); расхождение = конкретное несоответствие,
   вес зависит от единообразия линии.
6. **Прочие определения ВС РФ об отказе в передаче** — минимальный вес; сами по себе
   не формируют позицию, учитываются только как косвенное подтверждение.

При хронологическом конфликте (более поздний акт ВС противоречит более раннему акту
ВАС) — отмечать отдельно: возможна эволюция практики, а не просто расхождение.

## Жёсткие правила

1. **Никаких выдуманных актов.** Реквизиты, даты, номера дел — только из выдачи
   коннектора в этой сессии. Нет акта в базе — пиши «в базе коннектора не найдено».
2. **Цитаты — дословно.** Любой фрагмент в кавычках — посимвольная копия из `sections`
   (get_case_details), `matched_quotes` (find_term) или поля `position` (акты КС).
   Не цитируй по полю `snippet` (оно обрезано). Не дописывай слова, которых в тексте
   акта нет.
3. **Проверяется только мотивировочная часть.** Резолютивная часть (кто выиграл) и
   процессуальные выводы (распределение расходов, подсудность) не являются предметом
   проверки, если только сам вопрос не процессуальный.
4. **Не квалифицируй значимость за юриста.** Без эпитетов «ключевой», «важнейший»,
   «основополагающий». Реквизиты + суть; вес определит юрист.
5. **❓ ставится только после реального поиска.** Если поиск не дал результата —
   явно указывай, что поиск проводился, но ничего не найдено.

## Процесс

### Шаг 1. Прочитать акт и извлечь правовые тезисы

Из мотивировочной части акта извлечь атомарные правовые тезисы — то, что суд
утверждает как норму или её толкование применительно к спору. Не факты дела, не
оценка доказательств, а переносимые юридические конструкции.

Критерии хорошего тезиса:
- формулируется как правило: «[при условии X] наступает последствие Y»;
- очищен от фактуры (имена, суммы, даты убраны);
- содержит нормативную привязку, если суд её указал (статья, пункт);
- сцепленные доводы разнесены на отдельные тезисы.

Типичное число тезисов: 3–8. При 6+ тезисах — показать список пользователю и
дождаться подтверждения перед поиском.

### Шаг 2. Размечить каждый тезис перед поиском

Для каждого тезиса зафиксировать (внутренняя разметка):
- **нормы** — статьи и кодекс (фильтр `article` коннектора различает кодексы:
  «ст. 450 ГК» ≠ «ст. 450 АПК»);
- **ключевые юридические термины** — для bm25/find_term;
- **контр-формулировку** — во что тезис превращается, если его опровергнуть или
  ограничить (используется на шаге 3 для CONTRA-захода).

### Шаг 3. Два встречных поиска по каждому тезису

Сначала выбери корпус по предмету тезиса (см. раздел про источник практики):
«Высшие суды» по умолчанию, СИП для интеллектуальной собственности, КАС для
административных дел и нормоконтроля. Инструменты ниже названы для «Высших судов»;
для СИП и КАС используй их одноимённые аналоги (`sip_*`, `kas_*`).

**PRO-заход** — поиск подтверждающей практики:
- `casuslegal_search_practice` с тезисом в его собственной формулировке,
  `mode='hybrid'` (по умолчанию);
- при привязке к конкретной статье — добавить фильтр `article`;
- при наличии устойчивого дословного оборота — дополнительно `casuslegal_find_term`;
- `limit` 15–20.

**CONTRA-заход** — поиск опровергающей / ограничивающей практики:
- `casuslegal_search_practice` с контр-формулировкой тезиса;
- точечный `casuslegal_find_term` по оборотам исключений («само по себе не является»,
  «не влечёт», «при условии», «за исключением», «не лишает права» и т.п.);
- это отдельный вызов (или несколько), не совмещать с PRO-заходом.

**Обязательно**: просматривать блоки `constitutional_context` и `latest_practice`
отдельно от основного списка `results`. В `constitutional_context` может лежать
постановление КС, прямо опровергающее тезис; в `latest_practice` — свежая линия
коллегий ВС, сложившаяся после основного массива практики ВАС. У коннектора КАС
этих обзорных блоков нет (это корпус правоприменения) — там ориентируйся на
`results` и постраничную навигацию.

### Шаг 4. Классифицировать каждый тезис

На основе найденного присвоить статус:

| Статус | Условие |
|---|---|
| ✅ **Подтверждён** | Найден акт высшего суда с аналогичной позицией; противоречий не обнаружено |
| ⚠️ **Расхождение** | Найден акт высшего суда с противоположной или существенно ограничивающей позицией |
| ❓ **Не охвачен** | Поиск проведён; практика высших судов по данному вопросу в базе не найдена |

Один акт может быть одновременно PRO (по общему правилу) и CONTRA (по исключению).
Указывать обе роли с пояснением.

Прежде чем отклонить акт КС как «не по теме» — открыть через get_case_details:
сниппет и теги привязаны к фабуле, конституционно-правовой смысл нормы шире.

### Шаг 5. Достать дословные цитаты у опорных актов

Для 2–3 опорных актов по каждому тезису (приоритет — акты с высшим иерархическим
весом и при расхождениях) вызвать `get_case_details(case_id)` того коннектора, из
которого акт найден, и взять точную цитату из `sections`. У актов КС цитата берётся
из инлайн-поля `position` — отдельный вызов не нужен.

## Что скилл не делает

- Не оценивает правильность установления фактов и оценки доказательств.
- Не формулирует жалобу и не даёт процессуальных советов.
- Не прогнозирует исход обжалования.
- Не проверяет соблюдение процессуального закона (сроки, подсудность и т.п.),
  если только тезис не касается процессуального права.
